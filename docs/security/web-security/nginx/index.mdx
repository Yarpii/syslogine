# Nginx Security

Nginx is often the first layer exposed to the internet, which makes it one of the most important places to apply practical security controls.

This section focuses on **real-world Nginx hardening** for public-facing websites and applications. The goal is to help you reduce attack surface, block noisy probes, improve request handling, and apply safer defaults without turning your configuration into a mess.

## What you'll learn

In this section, you'll find focused guides for:

- **Scanner Blocking**: Stop common probes for WordPress, phpMyAdmin, and other well-known paths
- **Rate Limiting**: Slow down abusive clients and protect login pages or APIs
- **Bot Protection**: Filter unwanted traffic patterns and reduce noise
- **Security Headers**: Add browser-side protections with clear, maintainable policies
- **TLS Hardening**: Improve HTTPS configuration and certificate handling

## Best practices for this section

To keep the Nginx guides useful for the community, each page in this section should stay focused on **one topic only**.

That means:

- one guide for scanner blocking
- one guide for rate limiting
- one guide for headers
- one guide for TLS
- one guide for bot filtering

This makes it easier for readers to copy only what they need, test changes safely, and avoid mixing unrelated configuration patterns.

:::tip Keep configs modular
A great pattern for Nginx hardening is to place reusable snippets in a dedicated directory and include them inside the correct `server` blocks. That keeps your configs easier to audit, reuse, and maintain.
:::

:::warning Test every change
Always validate your configuration with `nginx -t` before reloading. Small syntax issues can break deployments, especially when working with includes and nested blocks.
:::
